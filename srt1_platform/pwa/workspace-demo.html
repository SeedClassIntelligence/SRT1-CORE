Sandbox & Connector

Isolate your intelligence. Connect your components. SRT-1 gives you deep, cross-module context mapping without re-indexing a single file.

1. Single-Folder Sandbox

Drop SRT-1 into any folder. It starts its own engine on a dedicated port, derived from the folder path. No config needed.

When you ask the AI to "fix the login flow," it only sees auth code. No bleed from payments. No confusion from frontend CSS. Pure, isolated intelligence.

● payments/ → Engine on port 8192   · 8 files, 31 functions

● api-gateway/ → Engine on port 7821 · 6 files, 22 functions

Each engine: independent process, independent manifest, independent dashboard.

2. Workspace Connector

Modules don't exist in a vacuum. Auth calls payments. The gateway routes to both. You need a bird's-eye view.

The Workspace Connector acts as a parent orchestrator. It doesn't re-read your code. Instead, it queries each running Sandbox engine on its port, collects their live manifests, and builds a unified cross-module dependency map.

── Workspace Connector ──
$ srt1-workspace --root ./my-platform
✓ Discovered 5 running Sandbox engines
✓ Collected 5 manifests (242 functions total)
✓ Mapped 24 cross-module imports
⚠ Circular dependency: auth ↔ api-gateway
Zero re-indexing. The Connector reads what's already running.
How you actually use it

SRT-1 becomes the local control layer between your repo, your assistant, and your live build.

You do not re-download your project into SRT-1. You register a local repository, SRT-1 builds repo intelligence, then the dashboard lets you open a WorkCell, plant a seed, dispatch it to a configured assistant adapter, and review the proposed work before it is accepted.

1

Register the repository

Start Core with srt1 start --repo /path/to/project --port 7484, or use the dashboard Repository Manager to add, launch, stop, and switch local runtimes.

2

Select a WorkCell

SRT-1 creates FileCells and WorkCells from repository understanding. A WorkCell is the bounded execution environment the assistant is allowed to operate inside.

3

Connect an assistant

Use Codex, Claude, Cursor, Copilot, an OpenAI-compatible local model, or another adapter. Session keys are supplied by the developer and do not need to be persisted by Core.

4

Plant a seed

A dashboard action, mobile action, MCP call, API request, or Slack-style intake can plant the same queue-first seed into the selected WorkCell path.

5

Watch the work

The cockpit shows the package path, WorkCell instructions, provider readiness, execution job, result payload, review lane, and verification state.

6

Preview and approve

If your app runs on a local dev port, SRT-1 can link that runtime beside the WorkCell so you can inspect the live build before accepting changes.

Boundary rule: the assistant does not get the whole repository by default. It receives the WorkCell package and allowed paths. Expansion to more files should be evidence-based or human-approved.
Language coverage

Repository understanding covers the languages teams actually ship.

Core uses Python AST parsing where available and structural extraction for common project files. The goal is not just reading code; it is producing reusable repository intelligence for FileCells, WorkCells, recall, reinjection, verification, and assistant handoff.
